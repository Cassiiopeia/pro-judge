# public-data — 공공데이터 활용 대회

## 기대
- 쓴 데이터의 이름·제공 기관·갱신 주기를 밝힌다.
- 데이터가 서비스의 핵심 기능에 실제로 쓰인다 (장식이 아니다).
- 정책·행정과 연결되는 지점이 있고, 실현할 기관이 누구인지 안다.
- 데이터 품질 문제(결측·지연)를 알고 대응한다.

## 보이지 않는 감점
- 출처 불명 데이터, 라이선스 확인 없음.
- 데이터 없이도 되는 서비스에 데이터를 끼워 넣음.
- 실현 주체(기관)가 없음.

## 추천 상한 규칙
```yaml
- rule: no-data-source
  cap: 4
  unlock: "데이터 이름·제공 기관·주소가 원문에 있어야 넘는다"
  source: inferred
  why: "공공데이터 대회에서 출처 없는 데이터는 활용으로 인정되지 않는다"
- rule: data-not-core
  cap: 6
  unlock: "데이터가 핵심 기능의 어느 단계에 쓰이는지 화면·흐름으로 보여야 넘는다"
  source: inferred
  why: "데이터가 장식이면 대회 취지와 맞지 않는다"
```

## 취지 질문
- 이 데이터가 없으면 서비스의 어떤 기능이 멈추나요?
- 데이터가 한 달 늦게 갱신되면 어떻게 되나요?
- 이걸 실제로 도입할 기관은 어디이고, 담당 부서는 어디인가요?

## 페르소나 후보
- 데이터 제공 기관 담당자 (데이터 활용 정확성)
- 데이터 분석가 (품질·방법론)
- 지자체 정책 담당자 (행정 적용 경로)
