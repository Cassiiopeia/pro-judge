# 어디서 찾나

신뢰 등급: **official**(공고·주최 기관 문서) > **reported**(언론·제3자) > **self**(팀이 만든 자료) > **user**(사용자 말).
같은 사실이 여러 곳에 있으면 높은 등급 하나를 근거로, 나머지는 `note`에 적는다.

## 대회 모드

| 주제 | 먼저 볼 곳 | 웹 검색어 틀 |
| --- | --- | --- |
| announcement | 사용자가 준 공고 URL·PDF, 주최 기관 공지 게시판 | `"<대회명>" <연도> 공고` |
| criteria | 공고의 심사기준 표, 오리엔테이션 자료, 활동 안내자료 | `"<대회명>" 심사기준 배점` |
| schedule | 공고 일정표 | `"<대회명>" <연도> 일정 본선` |
| submission | 공고의 제출물 표·별첨 양식, FAQ | `"<대회명>" 제출물 분량 양식` |
| penalties | 공고의 제외·실격·감점 조항, 유의사항 | `"<대회명>" 제외 기준 중복 제출` |
| judges | 공고의 심사위원 구성 문장, 전년도 보도 | `"<대회명>" 심사위원 구성` |
| past-winners | 주최 기관 자료실(자료집·ebook), 시상 보도 | `"<대회명>" <전년도> 수상작`, `"<대회명>" 자료집` |

- 역대 수상작 자료집이 PDF·ebook이면 쪽 범위로 나눠 `extract_target.py`로 뽑는다.
  FlipBuilder 같은 ebook 뷰어는 `files/search/book_config.js`에 쪽별 텍스트가 있는 경우가 많다
- 수상 명단(훈격)은 자료집보다 시상 보도에 있는 경우가 많다. 둘을 맞춰 본다
- 역대 수상작을 찾으면 setup이 보정 채점을 제안한다

## 대상 모드

| 근거 종류 | 먼저 볼 곳 |
| --- | --- |
| numbers | README·발표자료의 수치, 실증보고서, 저장소 통계(`repo_facts.py`) |
| proper-nouns | 비교 대상 서비스 이름, 협력 기관, 사용한 오픈소스 |
| demo | 배포 URL(열어 보기), 시연 영상, 발표자료의 화면 캡처 |
| field-test | 실증보고서, 사용자 테스트 기록, 설문 결과 |
| quote | 당사자 인터뷰, 사용자 후기 원문 |
| observation | 직접 열어 본 화면·코드 구조·문서 |

- 웹 검색으로 팀 자료를 찾을 때는 팀이 직접 올린 것(블로그·발표 영상·스토어 페이지)만 `self`로 적는다
- 저장소가 fork면 원본 이름을 README·GitHub "forked from"에서 확인해 `repo_facts.py --upstream`에 넘긴다
